> Level-1 slug 一律小写：`omission` / `addition` / `substitution`。

# 一、总体标注原则

## 原则1：主要失真类型 = 导致科学含义变化最大的操作

判断问题：

> 如果只能删除/修改一个问题，哪个问题会最大程度改变论文原始发现？

该类型作为 Primary。

---

## 原则2：次要失真类型 = 伴随发生，但不是核心错误

判断：

> 是否存在另一个独立的信息变化，并且该变化对理解有影响？

如果有：

标 Secondary。

---

## 原则3：不要因为同一个变化重复标注

例如：

论文：

> Gene X may regulate drought tolerance.

公众号：

> Gene X regulates drought tolerance.

不要：

Primary:

- Evidence omission

Secondary:

- Relation substitution

因为：

may 删除只改变确定性。

没有改变关系类型。

---

# 二、Level 1 优先级规则

当多个类别竞争时，采用：

```
Substitution    >Addition    >Omission
```

为什么？

因为：

## Omission

只是信息减少。

## Addition

增加新信息。

## Substitution

改变已有科学意义。

其中：

Substitution 对原论文意义破坏最大。

---

例如：

论文：

> Gene X is associated with drought response.

公众号：

> Gene X is a key drought resistance gene that improves crop yield.

包含：

1. associated → improves

Relation substitution

2. key gene

Significance addition

3. crop yield

Function/Application addition

最终：

Primary:

```
Substitution→ Relation substitution
```

Secondary:

```
Addition→ Function/Application addition
```

原因：

核心错误：

把关联变成因果。

---

# 三、Omission 内部冲突规则

---

# 情况1：

Context omission vs Mechanism omission

例：

论文：

> In Arabidopsis seedlings, Gene X activates ABA pathway to regulate drought response.

公众号：

> Gene X improves drought resistance.

删除：

- Arabidopsis seedlings
- ABA pathway

同时：

Context omission

Mechanism omission

判断：

看哪个导致主要错误。

---

## 如果导致范围扩大：

Primary:

```
Context omission
```

Secondary:

```
Mechanism omission
```

因为：

植物科学传播中：

Arabidopsis → plants

通常比机制压缩影响更大。

---

## 如果没有范围扩大：

例如：

论文：

> Gene X activates ABA pathway to regulate drought response.

公众号：

> Gene X regulates drought response.

Primary:

```
Mechanism omission
```

---

# 情况2：

Context omission vs Evidence omission

例：

论文：

> Gene X may improve drought tolerance in Arabidopsis.

公众号：

> Gene X improves drought tolerance.

删除：

- may
- Arabidopsis

判断：

Primary:

```
Context omission
```

Secondary:

```
Evidence omission
```

原因：

范围扩大通常比确定性提高更影响科学适用性。

---

# 四、Addition 内部冲突规则

---

# 情况1：

Function/Application addition vs Significance addition

例：

论文：

> Gene X regulates drought response.

公众号：

> Gene X is a breakthrough gene that can improve crop yield.

包含：

- breakthrough
- crop yield

判断：

Primary:

```
Function/Application addition
```

Secondary:

```
Significance addition
```

原因：

应用预测比价值评价更接近科学错误。

---

# 情况2：

Addition vs Substitution

这是最重要冲突。

---

案例：

论文：

> Gene X is associated with drought response.

公众号：

> Gene X is a drought-resistance gene that improves crop yield.

包含：

Addition:

- crop yield

Substitution:

- association → improves

判断：

Primary:

```
SubstitutionRelation substitution
```

Secondary:

```
AdditionFunction/Application addition
```

规则：

> 如果新增信息改变了原始科学关系，则 Substitution 优先。

---

# 五、Substitution 内部冲突规则

---

# 情况1：

Relation substitution vs Magnitude substitution

论文：

> Gene X contributes to drought tolerance.

公众号：

> Gene X determines drought resistance.

变化：

贡献 → 决定

既有：

Magnitude

也有：

Relation

判断：

Primary:

```
Magnitude substitution
```

因为：

关系类型没有变化：

仍然是功能影响。

变化主要是作用程度。

---

# 情况2：

Relation substitution vs Mechanism substitution

论文：

> Gene X affects drought response through ABA signaling.

公众号：

> Gene X directly controls drought resistance.

变化：

机制改变。

关系增强。

判断：

Primary:

```
Mechanism substitution
```

Secondary:

```
Relation substitution
```

---

# 六、跨类别冲突决策表

| 情况             | Primary                       | Secondary                     |
| -------------- | ----------------------------- | ----------------------------- |
| 删除条件 + 删除机制    | Context omission              | Mechanism omission            |
| 删除条件 + 删除不确定性  | Context omission              | Evidence omission             |
| 删除机制导致因果变化     | Relation substitution         | Mechanism omission            |
| 新增应用 + 因果增强    | Relation substitution         | Function/Application addition |
| 新增“首次/突破”+新增应用 | Function/Application addition | Significance addition         |
| 相关→因果 + 程度增强   | Relation substitution         | Magnitude substitution        |
| 贡献→决定          | Magnitude substitution        | 无                             |
| 删除may          | Evidence omission             | 无                             |

---

# 七、不可标注区（No distortion）

这是 benchmark 非常重要的一部分。

目标：

防止标注员把所有论文→科普差异都认为是失真。

---

# N0. 合理科学压缩（Acceptable compression）

## 定义

删除细节，但核心科学命题保持。

---

例：

论文：

> ABA activates SnRK2 kinases, which regulate downstream transcription factors involved in drought response.

公众号：

> ABA signaling regulates drought response.

不标。

原因：

机制细节减少，但科学关系保留。

---

# N1. 术语通俗化（Terminology simplification）

论文：

> reactive oxygen species accumulation

公众号：

> 植物产生氧化压力

不标。

---

# N2. 同义表达转换（Paraphrasing）

论文：

> regulates

公众号：

> controls

如果上下文中：

control 只是普通表达。

不标。

---

# N3. 去除非关键实验细节

例如：

论文：

> after 24 hours treatment

公众号：

> after treatment

不标。

---

# N4. 正常程度弱化

论文：

> strongly increases

公众号：

> increases

通常不标。

原因：

科学传播可能主动降低表达强度。

---

# N5. 一般背景知识补充

论文：

> Plants use photosynthesis.

公众号：

> Plants use sunlight to produce energy.

不标。

因为：

不是针对该论文的新科学 claim。

---

# 八、最终人工审核流程

建议标注员按以下顺序：

---

## Step 0

以本篇论文为唯一依据，证据能否支撑细粒度比对？

- 完全找不到对应 → `evidence_level=No_Evidence`，结束（不标 8 类，`has_distortion=null`）
- 主题相关但既不能充分证真也不能充分证伪 → `Weak_Evidence`，结束（同上）
- 至少一句直接对应核心断言 → `With_Evidence` → Step 1

**不可核实 ≠ 已判定失真类型。**

---

## Step 1

公众号是否完全支持论文？

Yes:

```
No distortion
```

结束。

---

## Step 2

是否改变论文已有科学关系？

Yes:

检查：

- association → causation
- indirect → direct
- mechanism changed

↓

Substitution

---

## Step 3

是否增加论文没有的信息？

Yes:

↓

Addition

---

## Step 4

是否删除论文重要限定？

Yes:

↓

Omission

---

## Step 5

是否存在第二个独立错误？

最多增加 Secondary。

---

# 九、最终输出格式建议（用于代码）

建议 annotation schema（slug 见 README_1.md）：

```json
{
  "evidence_level": "With_Evidence",
  "has_distortion": true,
  "primary_label": {
    "level1": "substitution",
    "level2": "relation_substitution"
  },
  "secondary_label": {
    "level1": "addition",
    "level2": "function_application_addition"
  },
  "severity": "moderate",
  "needs_manual_review": false,
  "uncovered_phenomenon": "",
  "reason": "Association changed into causal claim"
}
```

无失真：`has_distortion=false`，`primary_label.level2="no_distortion"`，`severity="none"`。  
证据不足：`has_distortion` 与 `primary_label` 均为 null。  
`severity` 取值：`none` / `mild` / `moderate` / `severe`。

---

# 十、一个重要建议

目前不要再增加类别。

现在更需要冻结：

1. **Primary/Secondary 决策规则**
2. **No distortion 边界**
3. **20-50 个困难案例测试**

因为 taxonomy 是否优秀，不取决于类别数量，而取决于：

> 两个标注员面对同一个 claim，是否能按照规则得到同一个结果。

目前这个体系已经具备形成 benchmark annotation guideline 的基础。下一步建议制作 **“边界案例库（hard cases）”**，因为真正决定一致性的不是普通案例，而是这些冲突案例。
